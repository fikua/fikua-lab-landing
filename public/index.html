How the ecosystem fits together

Five independent services, each owning one role of the EUDI Wallet architecture. No monolith — every box is its own deployable.

The Verifier and the OAuth2 Authorization Server live in the same service (idp.fikua.com) because in the OID4VCI authorization-code flow, the AS authenticates the citizen by verifying a wallet presentation — the two roles share state by design, not by accident.

What is the Digital Identity Lab

A learning lab I built and run alone to understand the EUDI Wallet ecosystem from the inside — not by reading the ARF, but by implementing every role in it and validating each one against the OpenID Foundation conformance suite.

Issuer

Issues EUDI PID as SD-JWT VC and mdoc via OID4VCI. Reads credential type definitions from the Attestation Registry instead of hardcoding them, and calls the Signature Service to sign every credential.

  • OID4VCI 1.0
  • SD-JWT VC / mdoc
  • DPoP / PAR / PKCE

Wallet

Holds credentials in the browser and presents them selectively. Talks to the Issuer and the Verifier directly — holder binding and selective disclosure following the HAIP profile.

  • Holder binding
  • Selective disclosure
  • HAIP 1.0

Verifier + Authorization Server

Validates credential presentations via OID4VP, and doubles as the OAuth2 Authorization Server for the OID4VCI authorization-code flow — a citizen authenticates by presenting a credential.

  • OID4VP 1.0 / DCQL
  • OAuth2 AS · RFC 9068
  • x509_san_dns / x509_hash

Attestation Registry

A catalogue of attestation/credential types per the ARF and ETSI TS 119 472 — claims, display metadata, and SD-JWT VC Type Metadata. Not a trust registry: it defines what a credential looks like, so Issuer and Verifier don't hardcode schemas.

  • ARF 3.0
  • ETSI TS 119 472
  • SD-JWT VC Type Metadata

Minimal, intentional stack

No frameworks, no magic. Issuer, Verifier/AS, and Attestation Registry are standalone Go services; every line of protocol code is a learning opportunity.

Go Issuer, Verifier/AS, and Attestation Registry — standard library first
TypeScript + Vite Wallet PWA, runs entirely in the browser
PostgreSQL Credential offers, sessions, attestation schemas
go-jose / jwx JWT, JWK, SD-JWT, DPoP token handling
Docker Compose + Traefik Single-command deployment on EU VPS
X.509 PKI eIDAS-aligned certificate chain, no DIDs
Java 25 + Spring Boot Digital Signature Service — CSC v1/v2 remote signing (Go port planned)
Shared Go CSC client crypto.Signer adapter used by Issuer and Verifier to call the Signature Service
